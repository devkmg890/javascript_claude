# 01. 용어사전

> 튜토리얼 중 새 용어가 나오면 여기에 계속 추가합니다. 짧게, 비유 위주로.
> 모르는 단어가 있으면 `Ctrl+F`로 검색하세요.

## 🌐 웹 기본

| 용어 | 설명 |
|---|---|
| 클라이언트 (Client) | 요청을 **보내는** 쪽. 예: 브라우저, 앱 |
| 서버 (Server) | 요청을 **받아서 응답하는** 쪽. 컴퓨터 자체 또는 그 위의 프로그램 |
| 프론트엔드 (Frontend) | 사용자 눈에 보이는 화면 부분. 우리 프로젝트에선 React |
| 백엔드 (Backend) | 화면 뒤에서 데이터 처리·저장을 하는 부분. 우리 프로젝트에선 Express 서비스들 |
| HTTP | 클라이언트와 서버가 대화하는 **약속(규칙)**. "요청(Request) → 응답(Response)" 구조 |
| HTTP 메서드 | 요청의 종류. `GET`(조회) `POST`(생성) `PUT/PATCH`(수정) `DELETE`(삭제) |
| 상태 코드 | 응답 결과 번호. `200` 성공, `201` 생성됨, `400` 잘못된 요청, `401` 로그인 필요, `403` 권한 없음, `404` 없음, `500` 서버 오류 |
| URL | 인터넷 주소. 예: `http://localhost:8000/api/items` |
| localhost | "내 컴퓨터 자신"을 가리키는 주소 (`127.0.0.1`) |
| 포트 (Port) | 한 컴퓨터 안에서 프로그램을 구분하는 **방 번호**. 예: gateway는 8000번 방 |
| JSON | 데이터를 주고받는 텍스트 형식. `{ "name": "볼펜", "qty": 10 }` |
| API | 프로그램끼리 대화하는 **창구/메뉴판**. "이 주소로 이렇게 요청하면 이걸 줄게" |
| REST API | URL과 HTTP 메서드로 자원(데이터)을 다루는 API 설계 스타일. 예: `GET /items`, `POST /items` |
| CORS | 브라우저가 "다른 주소의 서버"에 요청하는 것을 막는 보안 규칙. 서버가 허용해줘야 함 |

## 🟨 JavaScript / Node.js

| 용어 | 설명 |
|---|---|
| JavaScript (JS) | 원래 브라우저용 언어. 지금은 서버에서도 사용 |
| Node.js | JS를 **브라우저 밖(내 PC, 서버)** 에서 실행하게 해주는 프로그램 |
| npm | Node.js의 **패키지(라이브러리) 관리 도구**. 남이 만든 코드를 내려받아 씀 |
| 패키지 / 라이브러리 | 남이 만들어 둔 재사용 가능한 코드 묶음 |
| package.json | 프로젝트 정보와 사용하는 패키지 목록이 적힌 **명세서** |
| node_modules | 내려받은 패키지가 저장되는 폴더 (Git에 올리지 않음) |
| 비동기 (async/await) | 오래 걸리는 작업(DB 조회 등)을 **기다리는 동안 다른 일을 할 수 있게** 하는 방식 |
| 모듈 (import/export) | 코드를 여러 파일로 나누고 서로 가져다 쓰는 방법 |

## ⚙️ 백엔드

| 용어 | 설명 |
|---|---|
| 프레임워크 (Framework) | 개발의 **뼈대와 규칙**을 미리 제공하는 도구 |
| Express | Node.js용 가벼운 웹 서버 프레임워크 |
| 라우팅 (Routing) | "이 URL로 요청이 오면 이 코드를 실행" 하고 **길을 정해주는 것** |
| 미들웨어 (Middleware) | 요청이 최종 처리되기 전에 **중간에서 거치는 단계**. 예: 로그인 검사, 로그 기록 |
| 서비스 (Service) | 특정 기능을 담당하는 서버 프로그램 하나 |
| 마이크로서비스 (MSA) | 시스템을 **작은 서비스 여러 개로 쪼개는** 아키텍처 방식 |
| 모놀리식 (Monolithic) | 모든 기능을 **하나의 프로그램**에 넣는 방식 (MSA의 반대) |
| API 게이트웨이 | 모든 요청이 들어오는 **단일 입구**. 라우팅 + 인증 검사 담당 |
| 프록시 (Proxy) | 요청을 **대신 받아서 다른 곳에 전달**해주는 중계자 |
| 환경변수 (.env) | 비밀번호·포트 등 **코드 밖에 두는 설정값** |

## 🗄️ 데이터베이스

| 용어 | 설명 |
|---|---|
| DB (Database) | 데이터를 체계적으로 **저장·조회**하는 프로그램 |
| 관계형 DB (RDBMS) | 데이터를 **표(테이블)** 형태로 저장하고, 표끼리 관계를 맺는 DB |
| PostgreSQL | 무료 오픈소스 관계형 DB |
| 테이블 / 행 / 열 | 엑셀의 시트 / 한 줄 / 한 칸(항목) |
| SQL | DB에 명령하는 언어. `SELECT * FROM items;` |
| CRUD | Create(생성) Read(조회) Update(수정) Delete(삭제) — 데이터 기본 4가지 작업 |
| 기본키 (PK) | 각 행을 구분하는 **고유 번호** (예: 주민번호) |
| 외래키 (FK) | 다른 테이블의 PK를 가리키는 값. 표끼리 **연결고리** |
| ERD | 테이블과 관계를 그린 **DB 설계도** |
| 트랜잭션 (Transaction) | 여러 작업을 **전부 성공 or 전부 취소**로 묶는 것. 예: 출고 시 재고 차감 + 기록 생성 |
| 마이그레이션 (Migration) | DB 구조 변경을 **버전처럼 기록·적용**하는 방법 |

## 🔐 인증 / 보안

| 용어 | 설명 |
|---|---|
| IAM | Identity and Access Management. "누가 무엇에 접근 가능한지" 관리하는 **개념/분야** |
| 인증 (Authentication) | "너 **누구**야?" 확인. 로그인 |
| 인가 (Authorization) | "너 이거 **해도 돼**?" 확인. 권한 검사 |
| 해시 (Hash) | 원래 값으로 **되돌릴 수 없게** 변환하는 것. 비밀번호는 해시로 저장 |
| bcrypt | 비밀번호 해시에 많이 쓰는 알고리즘/라이브러리 |
| 토큰 (Token) | 로그인 성공 시 받는 **출입증** |
| JWT | JSON Web Token. 위조 여부를 검증할 수 있는 토큰 형식 |
| Access Token / Refresh Token | 짧게 쓰는 출입증 / 출입증을 재발급받는 용도의 긴 토큰 |
| RBAC | Role-Based Access Control. **역할(관리자/직원)** 에 따라 권한 부여 |
| HTTPS | 암호화된 HTTP |
| 솔트 (Salt) | 해시 전에 비밀번호에 섞는 무작위 값. 같은 비밀번호도 다른 해시가 됨 (bcrypt가 자동 처리) |
| SQL 인젝션 | 입력값에 SQL 조각을 넣어 **DB 명령을 조작**하는 공격. 예: `' OR '1'='1` |
| 파라미터 바인딩 | SQL과 값을 **따로** 전달해 값이 명령으로 해석되지 않게 하는 방법. `WHERE id = $1` |
| 입력 검증 (Validation) | 들어온 값이 형식·길이·범위에 맞는지 검사. **서버에서 반드시** 해야 함 |
| 화이트리스트 | "허용된 것만 통과" 방식. "금지된 것만 막기"(블랙리스트)보다 안전 |
| XSS | 웹페이지에 악성 스크립트를 심어 다른 사용자 브라우저에서 실행시키는 공격 |
| CSRF | 로그인된 사용자의 브라우저를 이용해 **본인도 모르게 요청을 보내게** 하는 공격 |
| IDOR | URL의 id 등을 바꿔 **남의 데이터에 접근**하는 공격 |
| Rate Limit | 일정 시간 동안 요청 횟수를 제한하는 것. 무차별 대입 공격 방지 |
| helmet | Express에 보안 관련 HTTP 헤더를 한 번에 설정해주는 패키지 |
| 최소 권한 원칙 | 프로그램/계정에 **꼭 필요한 권한만** 주는 원칙 |
| 감사 로그 (Audit Log) | 누가 언제 무엇을 했는지 남기는 기록 |
| OWASP Top 10 | 웹에서 가장 흔한 보안 취약점 10가지 목록 (보안 공부의 기준표) |
| npm audit | 설치된 패키지에 알려진 취약점이 있는지 검사하는 명령 |

## 🔤 정규식 (Regular Expression)

| 용어/기호 | 설명 |
|---|---|
| 정규식 (RegExp) | 문자열의 **패턴(형식)** 을 표현하는 작은 언어. 입력값 검증에 사용 |
| `^` / `$` | 문자열의 **시작** / **끝**. 검증할 땐 꼭 둘 다 붙여 전체를 검사 |
| `[abc]` / `[a-z]` | 괄호 안 문자 중 **하나** / 범위 |
| `\d` / `\w` / `\s` | 숫자 / 영문·숫자·`_` / 공백 |
| `{n}` / `{n,m}` | 정확히 n번 / n~m번 반복 |
| `+` / `*` / `?` | 1번 이상 / 0번 이상 / 0 또는 1번 |
| `(?=...)` | 전방탐색. "이런 문자가 **포함되어야** 함" 조건 (비밀번호 정책에 사용) |
| `test()` | JS에서 정규식이 맞는지 true/false로 확인. `/^\d+$/.test("123")` → `true` |
| ReDoS | 비효율적인 정규식에 긴 입력을 넣어 **서버를 멈추게** 하는 공격. 입력 길이를 먼저 제한해 방어 |

## 🖥️ 프론트엔드 (React)

| 용어 | 설명 |
|---|---|
| React | 화면을 **컴포넌트(부품)** 단위로 만드는 JS 라이브러리 |
| Vite | React 프로젝트를 빠르게 만들고 실행해주는 **개발 도구** |
| 컴포넌트 (Component) | 화면의 재사용 가능한 **부품**. 예: 버튼, 표, 로그인 폼 |
| JSX | JS 안에서 HTML처럼 생긴 문법으로 화면을 작성하는 방식 |
| state (상태) | 컴포넌트가 기억하는 **변하는 값**. 바뀌면 화면이 다시 그려짐 |
| props | 부모 컴포넌트가 자식에게 **넘겨주는 값** |
| Hook | `useState`, `useEffect`처럼 `use`로 시작하는 React 기능 |
| SPA | Single Page Application. 페이지 새로고침 없이 화면만 바뀌는 웹앱 |
| 라우터 (React Router) | URL에 따라 **다른 화면을 보여주는** 기능 |

## 📐 기획 / 설계

| 용어 | 설명 |
|---|---|
| 요구사항 | 시스템이 **해야 할 일** 목록. 기능 요구사항 / 비기능 요구사항(성능, 보안 등) |

| 아키텍처 | 시스템을 어떤 덩어리로 나누고 어떻게 연결할지에 대한 **구조** |
| 시스템 구성도 | 아키텍처를 **그림**으로 표현한 것 |
| API 명세서 | API 목록과 요청/응답 형식을 정리한 문서 |
| 시퀀스 다이어그램 | 요청이 **어떤 순서로** 누구를 거치는지 그린 그림 |
| MVP | Minimum Viable Product. **최소한으로 동작하는** 첫 버전 |

## 🏢 인프라 / 서버 분리 / 장애 대비

| 용어 | 설명 |
|---|---|
| 인프라 (Infrastructure) | 프로그램이 돌아가는 **기반 시설**. 서버, 네트워크, 저장소 등 |
| 물리 서버 | 실제로 존재하는 **서버 기계** |
| 가상 서버 (VM) | 물리 서버 한 대를 쪼개 만든 **가상의 컴퓨터**. 각자 독립된 OS와 IP를 가짐 |
| 클라우드 | 서버를 직접 사지 않고 인터넷으로 **빌려 쓰는** 서비스. AWS, 오라클 클라우드, GCP 등 |
| 인스턴스 (Instance) | 클라우드에서 빌린 **가상 서버 1대**를 부르는 말 |
| 프리티어 (Free Tier) | 클라우드 업체가 제공하는 **무료 사용 범위**. 넘으면 요금 발생 |
| 리눅스 / Ubuntu | 서버에서 가장 많이 쓰는 운영체제 / 그중 인기 있는 배포판 |
| SSH | 멀리 있는 서버에 **안전하게 접속해 명령을 내리는** 방법 |
| SSH 키 | 비밀번호 대신 쓰는 **열쇠 파일** 쌍(공개키/개인키). 비밀번호보다 안전 |
| 공인 IP / 사설 IP | 인터넷에서 보이는 주소 / **내부망에서만** 쓰는 주소 |
| 내부망 (VPC/서브넷) | 외부와 분리된 **우리 서버들끼리의 네트워크** |
| 방화벽 / 보안 그룹 | 어떤 포트로, 누가 접속할 수 있는지 정하는 **출입 규칙** |
| Nginx | 화면 파일 제공과 요청 전달(리버스 프록시)에 많이 쓰는 웹 서버 프로그램 |
| 리버스 프록시 | 외부 요청을 받아 **내부 서버로 대신 전달**해주는 중계 서버 |
| PM2 | Node.js 프로그램을 서버에서 **계속 켜두고, 죽으면 다시 살려주는** 도구 |
| 장애 (Failure) | 서버나 프로그램이 **멈추거나 오작동**하는 것 |
| 단일 장애점 (SPOF) | 그것 하나가 죽으면 **전체가 멈추는** 지점 |
| 장애 격리 | 장애가 **다른 곳으로 번지지 않게** 나눠두는 것 |
| 백업 / 복구 | 데이터 사본을 떠두는 것 / 사본으로 **되살리는** 것. 백업은 반드시 **다른 곳에** 보관 |
| pg_dump | PostgreSQL 데이터를 파일로 **백업**하는 명령 |
| 헬스체크 (Health Check) | 서버가 살아있는지 **주기적으로 확인**하는 것. 예: `GET /health` |
| 이중화 | 같은 역할의 서버를 **2대 이상** 두어 하나가 죽어도 버티게 하는 것 |
| 고가용성 (HA) | 서비스가 **거의 멈추지 않고** 계속 동작하는 성질 |
| 레플리케이션 (Replication) | DB 데이터를 다른 DB 서버에 **실시간 복제**하는 것 |
| 장애 조치 (Failover) | 주 서버가 죽으면 **예비 서버로 자동 전환**하는 것 |
| 로드밸런서 | 요청을 여러 서버에 **나눠 보내는** 장치/프로그램 |
| cron | Linux에서 **정해진 시간마다 명령을 자동 실행**하는 기능. 예: 매일 새벽 3시 백업 |
| 런북 (Runbook) | 장애 상황별 **대응 절차서**. "이럴 땐 이 순서로" |
| 503 Service Unavailable | "뒤쪽 서버가 지금 응답할 수 없음"을 뜻하는 상태 코드 |

| PATH (환경변수) | 터미널이 명령어 프로그램을 **찾아보는 폴더 목록** |
| VS Code 확장 | VS Code에 기능을 더하는 플러그인 |
| 린터 (ESLint) | 코드의 실수·나쁜 습관을 **찾아 알려주는** 도구 |
| 포매터 (Prettier) | 코드 모양(들여쓰기 등)을 **자동으로 정리**하는 도구 |
| 저장소 (Repository) | Git이 이력을 관리하는 폴더 (`.git` 숨김 폴더 포함) |
| 브랜치 (Branch) | 이력의 **갈래**. 기본 갈래는 `main` |
| 스테이징 (git add) | 커밋에 담을 파일을 **장바구니에 담는** 단계 |
| .gitignore | Git에 **올리지 않을 파일** 목록 (`.env`, `node_modules` 등) |
| psql / pgAdmin | PostgreSQL을 다루는 터미널 도구 / 마우스로 쓰는 관리 프로그램 |
| 슈퍼유저 | DB의 **최고 관리자 계정** (`postgres`). 앱에서는 쓰지 않음 |
| Git | 코드 변경 이력을 저장하는 **버전 관리 도구** (게임 세이브와 비슷) |
| 커밋 (Commit) | 변경 내용을 하나의 **세이브 포인트**로 저장 |
| GitHub | Git 저장소를 인터넷에 올려두는 서비스 |
| 로컬 / 원격 저장소 | 내 PC에 있는 저장소 / 인터넷(GitHub)에 있는 저장소 |
| origin | 원격 저장소의 **기본 별명** |
| push / pull | 로컬 → 원격 **올리기** / 원격 → 로컬 **내려받기** |
| working tree clean | 마지막 커밋 이후 **바뀐 파일이 없음** (정상 상태) |
| Docker | 프로그램을 실행 환경째 **상자(컨테이너)에 담아** 어디서나 똑같이 실행하게 하는 도구 |
| 컨테이너 / 이미지 | 실행 중인 상자 / 상자를 만드는 **설계도** |
| docker compose | 여러 컨테이너를 **한 번에** 실행·관리하는 도구 |
| 로그 (Log) | 프로그램이 남기는 **실행 기록** |
| 배포 (Deploy) | 만든 프로그램을 **실제로 사용할 수 있는 곳**에 올리는 것 |

## 📋 기획 · 설계

| 용어 | 설명 |
|---|---|
| 요구사항 | 시스템이 **무엇을 해야 하는가**를 적은 목록. 기능(무슨 일을 하나) / 비기능(얼마나 빠르고 안전한가)으로 나뉨 |
| 기능 요구사항 | "품목을 등록할 수 있다"처럼 **동작**을 적은 것 |
| 비기능 요구사항 | 속도, 보안, 백업처럼 **품질·조건**을 적은 것 |
| MVP | Minimum Viable Product. **일단 이것만 되면 쓸 수 있는** 최소 기능 묶음 |
| 유스케이스 | "누가(역할) → 무엇을 한다"로 쓴 사용 시나리오. 예: *직원이 출고를 등록한다* |
| 와이어프레임 | 화면의 **뼈대 그림**. 색·디자인 없이 무엇이 어디 있는지만 표시 |
| Out of Scope | 이번에 **만들지 않기로 정한 것**. 적어두지 않으면 범위가 계속 늘어남 |
| 역할 (Role) | 사용자를 묶는 분류. 예: 관리자(admin), 직원(staff). 권한은 역할에 붙임 |
| 세션 (Session) | 서버가 "이 사람은 로그인한 홍길동"이라고 **서버 쪽에 기억해 두는 것** |
| 쿠키 (Cookie) | 서버가 브라우저에 맡겨 두는 **작은 쪽지**. 요청할 때마다 자동으로 같이 보내짐 |

## 🏗️ 아키텍처 · DB 설계

| 용어 | 설명 |
|---|---|
| 아키텍처 | 시스템을 어떤 조각으로 나누고 어떻게 연결할지에 대한 **전체 구조** |
| 모놀리식 | 모든 기능이 **한 덩어리**인 구조. 만들기 쉽지만 한 곳이 죽으면 전부 멈춤 |
| 마이크로서비스(MSA) | 기능별로 **작은 서비스 여럿**으로 나눈 구조. 유연하지만 복잡함 |
| 게이트웨이 | 모든 요청이 거쳐가는 **단일 입구** 서버 (건물의 정문) |
| 프록시 | 요청을 **대신 전달**해주는 중개 역할 |
| 인증 (Authentication) | "너 누구야?" — 로그인으로 신원 확인 |
| 인가 (Authorization) | "너 이거 해도 돼?" — 권한 검사 |
| 시퀀스 다이어그램 | 요청이 **시간 순서**대로 어디를 거치는지 그린 그림 |
| Mermaid | 마크다운 안에 **글자로 그리는** 다이어그램. GitHub에서 그림으로 보임 |
| ERD | 테이블(네모)과 관계(선)를 그린 **DB 설계도** |
| PK (기본키) | 행을 **유일하게 구분**하는 값 |
| FK (외래키) | 다른 테이블의 PK를 가리키는 값. 없는 값을 못 넣게 DB가 막아줌 |
| UNIQUE / NOT NULL | 중복 금지 / 빈 값 금지 제약 |
| CHECK 제약 | "이 범위여야 한다"는 규칙을 DB에 새기는 것. 예: 수량 ≥ 0 |
| 인덱스 (Index) | 책의 **색인**. 자주 검색하는 컬럼에 만들면 조회가 빨라짐 |
| DDL / DML | 테이블을 만드는 SQL(CREATE) / 데이터를 다루는 SQL(SELECT, INSERT) |
| JOIN | 두 테이블을 공통 값으로 이어붙여 조회. **같은 DB 안에서만** 가능 |
| 소프트 삭제 | 행을 진짜 지우지 않고 `is_active = false`로 **숨기는** 방식 |
| 최소 권한 원칙 | 계정에 **꼭 필요한 권한만** 주는 것. 사고가 나도 피해 범위가 작아짐 |
